Crée une plateforme fintech bancaire moderne, professionnelle et responsive appelée [NOM DE LA PLATEFORME].

IMPORTANT :

* Il s’agit d’un prototype/sandbox.
* Aucun vrai argent ne doit être transféré.
* Utilise des comptes, soldes, cartes et transactions fictifs.
* Ne stocke jamais de vrais mots de passe bancaires, CVV ou données sensibles de carte.
* Prépare l’architecture pour pouvoir être connectée plus tard à des prestataires réglementés d’Open Banking et de paiement.

1. SITE CLIENT

Créer une interface moderne, premium et rassurante avec :

Tableau de bord

Afficher :

* Solde disponible
* Solde en attente
* Dernières transactions
* Virements récents
* Cartes associées
* Prêts en cours
* Financements obtenus
* Notifications

Compte bancaire

Permettre au client de :

* consulter son profil
* consulter ses coordonnées bancaires fictives
* modifier certaines informations
* consulter son historique
* télécharger un relevé fictif

Virements

Créer une page permettant de :

* créer un virement
* choisir un bénéficiaire
* saisir le montant
* saisir une référence
* consulter le statut du virement

Les statuts possibles sont :

* En attente
* En vérification
* Suspendu
* Autorisé
* Exécuté
* Refusé

Lorsqu’un virement est suspendu, afficher clairement la raison exacte définie par le système.

Exemples :

* Vérification d’identité requise
* Nouveau bénéficiaire
* Activité inhabituelle détectée
* Limite de transaction atteinte
* Vérification de sécurité requise

Ne jamais afficher un faux motif.

2. SYSTÈME DE VÉRIFICATION

Créer un système de sécurité permettant, selon les règles définies par l’administrateur, de demander :

* code OTP
* authentification à deux facteurs
* confirmation supplémentaire
* vérification d’identité

Pour le prototype, les codes peuvent être simulés.

Ne jamais demander au client de payer pour obtenir un code de sécurité ou pour débloquer son propre argent.

3. CONNEXION À DES COMPTES BANCAIRES EXTERNES

Créer une interface “Connecter une banque”.

Le client peut :

* rechercher sa banque
* sélectionner une banque fictive
* autoriser la connexion
* voir les comptes connectés
* synchroniser un solde fictif
* supprimer la connexion

Préparer une architecture compatible avec une future intégration Open Banking via un prestataire réglementé.

Ne jamais demander directement les identifiants bancaires réels au client.

4. CARTES BANCAIRES

Créer une section “Mes cartes”.

Permettre de :

* ajouter une carte de démonstration
* afficher les quatre derniers chiffres
* afficher la date d’expiration fictive
* bloquer/débloquer la carte
* définir une limite fictive
* consulter les transactions

Ne jamais stocker de numéro de carte complet ou de CVV.

5. MODULE DE PRÊTS

Créer une section “Prêts”.

Le client peut :

* consulter les prêts disponibles
* choisir un montant
* choisir une durée
* simuler les mensualités
* envoyer une demande
* suivre le statut de sa demande

Statuts :

* Brouillon
* Demande envoyée
* En analyse
* Informations supplémentaires requises
* Acceptée
* Refusée
* Décaissée

Afficher clairement les conditions du prêt.

6. MODULE DE FINANCEMENTS NON REMBOURSABLES

Créer une section “Financements”.

Afficher différents programmes fictifs de financement.

Pour chaque programme :

* nom
* montant maximum
* critères d’éligibilité
* description
* documents nécessaires
* date limite
* statut

Le client peut :

* consulter un programme
* vérifier son éligibilité
* déposer une demande
* joindre des documents fictifs
* suivre l’avancement

Statuts :

* Demande envoyée
* En étude
* Documents requis
* Approuvée
* Refusée
* Financement accordé

Ne jamais présenter un financement fictif comme une garantie de recevoir de l’argent réel.

7. ESPACE ADMINISTRATEUR

Créer un dashboard administrateur séparé et sécurisé.

L’administrateur peut voir :

Vue générale

* nombre de clients
* comptes actifs
* transactions
* virements suspendus
* demandes de prêts
* demandes de financement
* alertes de sécurité

Gestion des clients

* rechercher un client
* consulter son profil
* voir son historique
* suspendre/réactiver un compte de démonstration
* consulter les activités
* gérer les niveaux de vérification

Gestion des virements

Créer une interface permettant à l’administrateur de :

* consulter tous les virements
* rechercher par client
* rechercher par montant
* filtrer par statut
* suspendre une transaction de démonstration
* autoriser une transaction
* refuser une transaction
* modifier le motif de suspension
* consulter l’historique des décisions

Créer un système de règles configurable.

Exemples :

Règle 1 :
Si montant > 5 000 €, déclencher une vérification supplémentaire.

Règle 2 :
Si bénéficiaire nouveau, mettre la transaction en vérification.

Règle 3 :
Si activité inhabituelle détectée, suspendre temporairement la transaction.

Règle 4 :
Si niveau de vérification insuffisant, demander une vérification.

L’administrateur peut activer/désactiver ces règles et modifier leurs paramètres.

IMPORTANT :
Ne crée pas de système permettant à l’administrateur de retenir arbitrairement les fonds d’un utilisateur réel ou de lui demander de payer des frais pour les débloquer.

8. MOTIF DU BLOCAGE

Lorsqu’une transaction est suspendue, le client doit pouvoir cliquer dessus et voir :

“Pourquoi cette transaction est-elle suspendue ?”

Afficher :

* statut
* date
* montant
* motif
* action nécessaire
* délai estimé, uniquement lorsqu’il existe réellement
* bouton permettant de compléter la vérification

Exemple :

TRANSACTION SUSPENDUE

Montant : 2 500 €
Statut : Vérification requise

Motif :
“Cette transaction nécessite une vérification de sécurité supplémentaire.”

Action requise :
“Confirmez votre identité pour poursuivre.”

9. JOURNAL D’AUDIT

Créer un système d’audit enregistrant :

* utilisateur ayant effectué l’action
* action réalisée
* date
* heure
* transaction concernée
* ancienne valeur
* nouvelle valeur
* adresse IP fictive pour le prototype

Aucune action administrative importante ne doit pouvoir être supprimée silencieusement.
